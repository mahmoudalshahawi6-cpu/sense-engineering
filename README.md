# SENSE — Engineering Digital Libraries

**Your Engineering Knowledge Hub**  
منصة عربية لعرض وبيع المكتبات الرقمية الهندسية: ميكاترونكس، ميكانيكا، كهرباء، وبرمجة.

> هذه حزمة مصدر قابلة للتشغيل والتطوير. لم يتم نشرها بعد على نطاق عام، ولا تتضمن مفاتيح خدمات أو حساب مدير جاهز. يجب إعداد قاعدة البيانات والتخزين والبريد وإنشاء حساب الإدارة قبل استقبال عملاء.

## 1. ما الذي تحتويه الحزمة؟

- واجهة عربية RTL متجاوبة تحمل هوية SENSE.
- صفحات رئيسية وصفحات مستقلة للمكتبات الأربع.
- تسجيل حسابات وتسجيل دخول وجلسات مستخدمين.
- شراء لمرة واحدة لكل مكتبة، مع إثبات تحويل وموافقة إدارية يدوية.
- صلاحية دائمة للمكتبة التي تم اعتماد شرائها.
- لوحة إدارة لمراجعة الطلبات وإدارة المستخدمين والمكتبات والأقسام والموارد وبيانات الدفع.
- قارئ محتوى محمي بعلامة مائية مرتبطة بحساب المستخدم.
- تخزين محلي للتطوير، أو Supabase Storage خاص للإنتاج على منصات Serverless.

## 2. المتطلبات

- Node.js 22 LTS (أو 20.9 فأحدث وفق متطلبات Next.js).
- PostgreSQL (Supabase أو مزود PostgreSQL آخر).
- مشروع Supabase Storage عند النشر على Netlify/Vercel.
- حساب Resend ونطاق مرسل موثّق لإرسال تأكيد البريد واستعادة كلمة المرور.

## 3. التشغيل المحلي

1. فك ضغط المشروع وافتح مجلده في VS Code.
2. ثبّت الاعتماديات:

```bash
npm install
```

3. انسخ `.env.example` إلى `.env.local` واملأ القيم الحقيقية.
4. تأكد من أن قاعدة PostgreSQL تعمل، وأن `DATABASE_URL` يشير إليها.
5. أنشئ الجداول:

```bash
npx drizzle-kit push
```

6. أنشئ هياكل المكتبات كمسودات غير منشورة:

```bash
node scripts/seed.mjs
```

لا ينشئ Seed حسابات تجريبية أو بيانات دفع أو أسعارًا أو فيديوهات وهمية. ويُنشئ المكتبات والأقسام والموارد كمسودات مخفية؛ استبدل النصوص التأسيسية بمحتوى حقيقي قبل النشر.

7. شغّل الموقع:

```bash
npm run dev
```

افتح `http://localhost:3000`.

## 4. متغيرات البيئة

راجع `.env.example`. أهم المتغيرات:

- `NEXT_PUBLIC_SITE_URL`: رابط الموقع النهائي، مثل `https://sense-engineering.netlify.app` بعد أن يكون الاسم قد خُصص لك.
- `DATABASE_URL`: رابط PostgreSQL. لمزودي السحابة استخدم رابط SSL الذي يوفره المزود.
- `AUTH_SECRET`: مفتاح طويل عشوائي. في الإنتاج التطبيق يرفض البدء إذا لم يتم ضبطه.
- `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY`: مطلوبان لاستخدام Supabase Storage. احتفظ بمفتاح Service Role في متغيرات الخادم فقط، ولا تضعه في متغير يبدأ بـ `NEXT_PUBLIC_`.
- `SUPABASE_PRIVATE_BUCKET`: الحاوية الخاصة الافتراضية `sense-private` لحفظ الملفات وإثباتات الدفع.
- `SUPABASE_PUBLIC_BUCKET`: الحاوية العامة الافتراضية `sense-media` لصور الأغلفة فقط.
- `RESEND_API_KEY` و`RESEND_FROM_EMAIL`: لإرسال روابط تأكيد البريد واستعادة كلمة المرور وإشعارات الطلبات. يجب توثيق نطاق المرسل في Resend.
- `ADMIN_NOTIFY_EMAIL`: (اختياري) بريد المدير الذي تصله رسالة عند وصول طلب شراء جديد.
- `NEXT_PUBLIC_SUPPORT_EMAIL` و`NEXT_PUBLIC_SUPPORT_PHONE` و`NEXT_PUBLIC_BUSINESS_ADDRESS`: بيانات التواصل الظاهرة للزوار؛ تترك فارغة حتى تضيف بياناتك الفعلية.

توليد مفتاح الجلسات:

```bash
openssl rand -hex 48
```

## 5. إعداد Supabase Storage للإنتاج

أنشئ في Supabase Storage حاويتين:

1. `sense-private` — **Private**. تُخزّن فيها ملفات المكتبات وإثباتات التحويل.
2. `sense-media` — يمكن جعلها **Public** لأنها مخصصة لأغلفة المكتبات والصور العامة فقط.

لا تجعل `sense-private` عامة، ولا تنشر `SUPABASE_SERVICE_ROLE_KEY` في الواجهة الأمامية. عمليات الملفات في هذا المشروع تمر عبر الخادم بعد التحقق من الجلسة والصلاحية.

في بيئات Serverless مثل Netlify، لا تعتمد على القرص المحلي لتخزين دائم؛ استخدم Supabase Storage. التخزين المحلي مخصص للتطوير أو لخادم يمتلك قرصًا دائمًا.

## 6. إنشاء حساب المدير

لا توجد كلمات مرور أو حسابات إدارة افتراضية في هذه الحزمة.

بعد إعداد `.env.local` وقاعدة البيانات، أنشئ حسابك الإداري بنفسك:

```bash
node scripts/manage-admin.mjs create "اسم مدير المنصة" you@example.com "اكتب-كلمة-مرور-قوية-هنا"
```

كلمة المرور يجب أن تكون 10 أحرف على الأقل. لا تضعها في مستودع Git أو ملف عام. لإدارة حسابات لاحقًا:

```bash
node scripts/manage-admin.mjs list
node scripts/manage-admin.mjs promote you@example.com
node scripts/manage-admin.mjs demote you@example.com
node scripts/manage-admin.mjs password you@example.com "كلمة-مرور-جديدة-قوية"
```

## 7. دورة الشراء المعتمدة

1. الزائر يشاهد فيديو المعاينة المجاني وصفحة المكتبة.
2. ينشئ حسابًا أو يسجّل الدخول.
3. يختار وسيلة الدفع التي أدخلتها الإدارة: InstaPay أو محفظة أو تحويل بنكي.
4. ينفّذ التحويل ويرفع صورة/ملف إثبات.
5. ينشأ طلب بحالة `pending` ويظهر في لوحة الإدارة.
6. تراجع الإدارة عملية التحويل ثم توافق أو ترفض مع سبب.
7. عند الموافقة، ينشأ سجل ملكية دائم للمكتبة في حساب العميل.
8. يستطيع العميل العودة إليها بعد تسجيل الخروج والدخول من جديد.

لا يتم تفعيل المكتبة بمجرد رفع صورة الإثبات؛ التفعيل يتطلب موافقة المدير.

## 8. تأكيد البريد واستعادة كلمة المرور

تستخدم الروابط الآمنة المرسلة بالبريد. اضبط `RESEND_API_KEY` و`RESEND_FROM_EMAIL` بعد توثيق نطاق الإرسال. روابط التأكيد صالحة لمدة 24 ساعة، وروابط استعادة كلمة المرور صالحة لمدة ساعة وتستخدم مرة واحدة. لا تظهر رموز الاستعادة في صفحات الواجهة.

### خطوات تفعيل البريد خطوة بخطوة

1. أنشئ حسابًا في Resend وافتح صفحة Domains.
2. تحتاج دومينًا تملكه أنت وتتحكم في DNS الخاص به. رابط Netlify المجاني مثل `sense-engineering.netlify.app` ليس دومينًا تملك سجلات DNS الخاصة به، لذلك لا يصلح كعنوان مرسل موثّق في Resend.
3. أضف الدومين المملوك لك في Resend. الأفضل استخدام نطاق فرعي مخصص للرسائل مثل `mail.yourdomain.com` أو `notify.yourdomain.com`.
4. انسخ سجلات DNS التي يعرضها Resend (مثل DKIM وSPF وأي سجل مطلوب) وأضفها في لوحة DNS لدى الشركة التي اشتريت منها الدومين. لا تخمّن القيم؛ انسخ القيم التي يعطيها Resend لحسابك كما هي.
5. ارجع إلى Resend واضغط Verify وانتظر حتى تظهر حالة Verified.
6. افتح صفحة API Keys وأنشئ مفتاحًا بصلاحية Sending فقط ومقيّدًا بالدومين الموثّق إن كان الخيار متاحًا. احتفظ بالمفتاح سرًا.
7. في Netlify افتح Site configuration → Environment variables وأضف:
   - `RESEND_API_KEY` = مفتاح Resend.
   - `RESEND_FROM_EMAIL` = مثل `SENSE <no-reply@mail.yourdomain.com>` ويجب أن يطابق الدومين الموثّق.
8. أضف `NEXT_PUBLIC_SITE_URL` كرابط موقعك الحالي، ثم أعد نشر الموقع حتى تُحمّل متغيرات البيئة.
9. سجل الدخول كمدير وافتح `/admin/settings` واضغط «إرسال رسالة اختبار». إذا وصلت رسالة الاختبار إلى بريد المدير (افحص Spam أيضًا)، جرّب تسجيل حساب جديد واطلب تأكيد البريد.

ملاحظة: نطاق Resend التجريبي `resend.dev` مخصص للاختبار ويمكنه الإرسال فقط إلى عنوان البريد المرتبط بحساب Resend. لا يرسل لطلابك قبل توثيق دومين تملكه وتغيير عنوان المرسل إلى ذلك الدومين. كما أن ضبط متغيرات البيئة وحده لا يكفي ما لم يكن الدومين موثّقًا.

## 9. حماية المحتوى

- ملفات المكتبات وإثباتات التحويل تُحفظ في تخزين خاص.
- مسار قراءة الملفات يتحقق من الجلسة ومن ملكية المكتبة أو مجانية المورد.
- الروابط الموقعة للمحتوى قصيرة العمر ومقيدة بالمستخدم والمورد.
- إثباتات الدفع لا يمكن مشاهدتها إلا من صاحب الطلب أو المدير.
- قارئ PDF يعرض علامة مائية بحساب المشترك.
- تعطيل زر التنزيل أو الطباعة لا يمنع تصوير الشاشة أو النسخ الخارجي بنسبة 100%؛ الحماية هنا تقلل مشاركة الملفات وتمنع الوصول غير المصرح به.

## 10. إضافة المكتبات والمحتوى

1. سجّل الدخول بحساب المدير ثم افتح `/admin/libraries`.
2. أضف المكتبة أو افتح مكتبة موجودة.
3. أضف الأقسام والموارد.
4. أضف رابط فيديو المعاينة، والسعر، والغلاف، وراجع الوصف.
5. ارفع المحتوى الفعلي أو أضف رابطًا مرخصًا.
6. انشر المكتبة فقط بعد مراجعة جميع الأقسام والملفات والروابط والأسعار.

المكتبات التي ينشئها Seed تكون مخفية وغير منشورة. لا تنشر نصوص Seed التأسيسية باعتبارها موادًا تعليمية مكتملة؛ استبدلها بالمحتوى النهائي الذي تملكه أو لديك تصريح باستخدامه.

من لوحة المدير، افتح المكتبة ثم منطقة «الملفات والدروس والمصادر». اختر القسم، واكتب عنوان المورد، ثم اختر «ملف محمي» وحدد الملف من جهازك واضغط الحفظ. كل ملف يُضاف كسجل مستقل ويمكن وضعه في أي قسم. الرفع الحالي يقبل PDF والصور وMP4/WEBM وTXT/MD حتى 4 ميجابايت للملف الواحد؛ حوّل Word وExcel إلى PDF أولًا حتى يمكن عرضهما داخل قارئ الموقع. لا ترفع ZIP أو ملفات Office بصيغتها الأصلية إذا كان المطلوب منع التنزيل وعرض المحتوى داخل الموقع.

الرفع الحالي يمر عبر Server Action، لذلك حدّه 4 ميجابايت للملف الواحد. للمكتبات الكبيرة أو رفع ملفات متعددة/كبيرة نوصي بتطوير الرفع المباشر إلى Supabase باستخدام Signed Upload URLs أو TUS resumable uploads؛ لا ترفع الملفات الكبيرة عبر نموذج Serverless عادي.

## 11. النشر على Netlify

1. ارفع المشروع إلى مستودع Git خاص على GitHub.
2. من Netlify اختر **Add new site → Import an existing project**، ثم اربط المستودع.
3. استخدم أمر البناء `npm run build` واترك Netlify يكتشف Next.js Runtime/Plugin المناسب.
4. أضف متغيرات البيئة المطلوبة من إعدادات الموقع: `DATABASE_URL`, `AUTH_SECRET`, `NEXT_PUBLIC_SITE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, أسماء الحاويات، وإعدادات Resend وبيانات التواصل.
5. تأكد من إضافة `NEXT_PUBLIC_SITE_URL` كرابط Netlify النهائي بعد تخصيص اسم الموقع.
6. أنشئ الجداول وشغّل Seed مرة واحدة من بيئة آمنة متصلة بقاعدة البيانات، ثم أنشئ حساب المدير.
7. اختبر تسجيل المستخدم، رفع الإثبات، مراجعة الطلب، تفعيل المكتبة، قراءة الملفات من حساب العميل، ومنع حساب آخر من الوصول.

لا تضع مفاتيح Supabase أو Resend أو كلمات المرور داخل ملفات الواجهة أو GitHub. أضفها في Netlify Environment Variables فقط.

## 12. مراجعة السياسات القانونية

صفحة الاسترداد المرفقة نص مبدئي، وليست رأيًا قانونيًا أو سياسة نهائية. اعتمد نص الاسترداد والخصوصية والشروط وفق نشاطك والقوانين المصرية ذات الصلة، واعرضه على المشتري قبل الدفع. لا تبدأ استقبال المدفوعات قبل إضافة بيانات التواصل وبيانات التحويل الفعلية.

## 13. فحص ما قبل استقبال العملاء

- [ ] تم ضبط رابط الموقع النهائي وHTTPS.
- [ ] تم ضبط `AUTH_SECRET` قوي وفريد.
- [ ] تم ضبط PostgreSQL وSupabase Storage وحاوية الملفات الخاصة.
- [ ] تم إنشاء حساب المدير وتغيير كلمة مروره بشكل آمن.
- [ ] تم ضبط بيانات الدفع الفعلية من `/admin/settings`.
- [ ] تم ضبط خدمة البريد وإجراء اختبار تأكيد الحساب واستعادة كلمة المرور.
- [ ] تم رفع المكتبات النهائية واستبدال نصوص Seed التأسيسية.
- [ ] لكل مكتبة سعر صحيح وفيديو معاينة ومحتوى تمت مراجعته.
- [ ] تم اختبار طلب شراء بمستخدم تجريبي، ثم الموافقة اليدوية وظهور المكتبة في الحساب.
- [ ] تم التأكد أن مستخدمًا غير مشترك لا يستطيع الوصول للمحتوى الخاص.
- [ ] تم إعداد نسخ احتياطي لقاعدة البيانات والملفات.
